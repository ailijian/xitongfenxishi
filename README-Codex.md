## 2. 产品目标与边界

产品名称暂定 **「软考冲刺 · 系统分析师」**。用户是单个准备 2026 年下半年上海考区软考高级《系统分析师》的考生。考试首日是 2026-10-24，实际日期/批次以准考证为准。默认学习启动日期为 2026-10-11，但用户可以在设置中修改启动日；学习第 N 天按启动日计算，不应写死到代码中。

核心理念：**知识点达标制**，非学习时长制。首页不出现“今天学习 7 小时”、强制倒计时或累计时长目标。只有“完整模考”可选或推荐计时。用户不必按固定小时完成，但要知道本日新增知识通过数量、复习欠账、案例/论文目标以及考试整体进度。

### MVP 范围

- 手机优先的中文响应式 H5，视口 320—430px 体验优先，桌面端亦能使用。
- 支持安装到手机主屏幕（PWA）和首次加载后的离线访问。
- **第一版不需要登录、后台、云同步、付费能力或 LLM 接口**。
- 进度、错题、案例作答、论文草稿保存到 IndexedDB；至少支持“导出全部数据为 JSON”和“从 JSON 恢复”以及恢复前预览/二次确认。
- 明确告知用户：V1 数据存在当前浏览器/设备，换手机不会自动同步，需导出导入；清理浏览器存储可能使数据丢失。每次知识/作答变更应立即持久化，离线可用。

## 3. 推荐技术栈

React + TypeScript + Vite + Tailwind CSS + React Router + Dexie（IndexedDB）+ vite-plugin-pwa；Zod 用于导入及备份校验；Vitest 用于单元测试、Playwright 用于移动端关键流程回归。避免与单用户离线应用无关的复杂工程。可使用相近稳定栈，但必须在 README 说明原因。

### 数据验收（构建阻断条件）

- 恰好 76 条知识卡，优先级 57 A / 19 B。
- 恰好 150 道互不重复的单选题，题号与正确选项、解析完整。
- 恰好 9 套案例和 10 个论文专题，各 ID 唯一。9 套案例必须包含题干、分问、参考答案和完整 25 分自评采分标准；不得只导入 Excel 中的简短介绍。
- 所有单选选项均非空；关联答案只能是 A/B/C/D；知识卡/试题的 HTML 内容必须安全呈现。
- 构建时输出 `content-import-report.md`：实际数量、缺失字段、重复 ID、人工检查项目、来源表与行号。缺少核心答案、案例参考答案或采分点时不得悄悄生成虚构内容，必须报告和补齐来源信息。
- 维护 `contentVersion` 和稳定 ID；升级知识文本不得清空或错配已有学习进度。

### 知识与题目的关系

为卡片添加 `relatedQuestionIds`。Excel 中的“知识模块”和“问题知识模块”命名不完全一致，**不能只根据模块名称直接视为精准题卡对应**。先用关键词产生候选，再人工或规则逐题确认；对于没有可信匹配选择题的知识卡，提供不依赖外部 AI 的“闭卷回忆要点自检”作为替代，并标记为“自评验证”，不要伪装成客观判分。

## 5. 7 天通关计划（确定性起点，允许动态重排）

默认首轮知识新学任务：

| 天 | 知识卡 ID | 当日首轮通关数量 |
|---|---|---|
| D1 | K001—K014，K075 | 15 |
| D2 | K015—K029 | 15 |
| D3 | K030—K041，K069—K071 | 15 |
| D4 | K042—K055，K074 | 15 |
| D5 | K056—K068，K072，K073，K076 | 16 |
| D6 | 不安排新增卡，完成综合模考 75 题、任选/系统推荐 3 套案例、1 篇完整论文 | 0 |
| D7 | 不安排新增卡，复习逾期卡和错题，检查 A 级卡巩固情况，至少列 2 个论文提纲并修订论文 | 0 |

其中 D1—D5 计划总计 76 条，卡片不能重复分配、不能遗漏。D1 至 D5 每天还安排相应章节选择题；D1 案例 C01/C02，D2 C04，D3 C03/C07，D4 C05/C06，D5 C08/C09（C07—C09 为补充题，考试时仍应围绕选题能力挑强项）。论文从 D1 开始收集真实项目素材；D2—D5 逐日形成论文提纲，D6 写完整论文。实际执行顺序优先级：**到期复习 > 前日未通关卡 > 今日新学卡 > 配套练习 > 案例/论文**。

### 动态计划规则

- 用 `studyStartDate` 计算学习第 N 天；用户修改起始日后保留所有学习记录，不清零。
- 已经通过首轮验收的卡片不再强制列为“今天的新学任务”。
- 截止 D5 未完成的卡片标记为欠账，自动排入下一学习日，并显示“原计划 / 本日新增 / 历史欠账”；剩余量可按后续可用首轮学习日平均分配，优先 A 级，**不得将欠账藏起来或假定已经掌握**。
- 如果用户学习超前，自动减少后续的新增知识任务；如果落后，显示预计需要完成的卡数，不设置每天最高卡数，允许自由继续下一天的内容。
- D6/D7 可以继续补未过关知识，但页面要明确说明这会挤占模考和复习；允许由用户手动重排任务。

### 掌握判定（必须与点击阅读分开）

每张卡记录 `未开始 → 学习中 → 初步掌握 → 巩固掌握`，同时存在 `需复习` 状态。

- 学习界面先展示概念讲解与易错点，再给闭卷自测提示；用户先独立作答/思考，揭示答案后对照关键点自检。
- **初步掌握**：关键点自检通过，并且至少完成一道可信关联选择题（若存在）；没有关联题时允许通过自评问答完成，但须显示“仅自评”。只阅读、翻页、点击“我看过”不能算掌握。
- **巩固掌握**：完成初步掌握至少 24 小时后再进行一次闭卷复测，成功才升级；复测失败转入待复习，不得维持巩固状态。
- 相关选择题出错，加入错题本；若反映当前卡的关键知识缺失，则提醒该卡需重新复习。保留所有学习尝试和原始时间戳，支持可靠统计。
- A/B 优先级影响排序及复习频率；不要把未作答的知识点计作已掌握。
- 首页分别显示首轮通过 0/76、巩固掌握 0/76，以及 A 级巩固情况，绝不只展示“学习完成率”单一数字。

## 6. 核心页面和交互

1. **首页 `/`**：考试倒计时（考期 2026-10-24/25，具体批次以准考证为准）、当前 Day N/7、今日首轮通关目标与已达标数、到期复习、历史欠账、一键继续学习、案例/论文任务、各科准备程度（训练指标，不是官方预测分数）。
2. **知识 `/learn`**：知识卡按 A/B、模块、状态检索/筛选；单卡展示“必会概念→易错点→先想答案→揭示→自检→关联刷题”；显示复习提醒和掌握记录。
3. **刷题 `/practice`**：章节题 75 道、错题重练、独立完整模考试卷 75 道。章节题交卷后可立即看解析，模考模式**整卷交卷后**才展示答案和成绩；保留答题状态，支持退出继续、跳题、题号导航、收藏。错题可按模块过滤与二刷。
4. **案例 `/cases`**：9 套完整场景；题干、分问独立展开，用户输入答案后显示参考答案和逐点评分自评表，总分 25；显示漏掉的采分点。可保存多次训练历史。
5. **论文 `/essays`**：10 个论文专题、真实项目素材库表单（项目背景、真实职责、架构/决策、难点、验证结果、反思）、大纲编辑器、正文草稿、字数统计、复制/导出 TXT 或 Markdown；提供“是否切题、是否有权衡与验证”自查。**不自动假造项目经历、不声称按官方评分标准自动阅卷**。
6. **进度与设置 `/progress`**：知识掌握分布、A/B 完成情况、章节正确率、模考记录、案例自评分、论文进度；导出/恢复全部用户数据、重置需二次确认、数据来源说明、计划启动日设置。

底部导航建议：**今日 / 知识 / 刷题 / 实战 / 我的**；实战内分案例和论文。每页保持一屏一个主要任务，提供明确的“下一题/下一知识”操作，适合碎片化手机使用。

## 7. 视觉与交互要求

- 中文、清爽、专业、低干扰，不要考试培训机构式密集广告/弹窗；不要炫技型图表、过度动画。
- Mobile-first：320/375/390/430px 下不得横向滚动；正文字号至少 15—16px，按钮点击热区 ≥ 44px，长题干自然换行，底部操作条适配安全区。
- 一次显示一道选择题；答题按钮大且容易点；公式/代码/长中文正确换行，必要时使用可横向滚动的局部代码区而不是整页滚动。
- 默认浅色主题，兼容系统深色模式；良好对比度、可读性、键盘无障碍；避免颜色是唯一状态指示。
- 弱网或断网情况下所有已经缓存的知识内容、题目、案例、论文继续可用；提示首次访问需要联网加载资源。

## 8. 存储与数据质量

建议结构：

- `KnowledgeCard {id, module, title, essentials, pitfalls, priority, relatedQuestionIds, sourceRef}`
- `Question {id, set: 'chapter'|'mock', module, priority, stem, options, answer, explanation, relatedKnowledgeIds, sourceRef}`
- `Case {id, title, priority, scenario, questions: [{text, points, referenceAnswer, scoringRubric}], totalPoints: 25, sourceRef}`
- `EssayTopic {id, title, priority, outline, scenario, evidenceChecklist, sourceRef}`
- `CardProgress {cardId, status, firstPassAt, reviewDueAt, consolidatedAt, validationMethod, reviewAttempts[]}`
- `QuestionAttempt {id, questionId, set, selectedOption, correct, submittedAt}`
- `CaseAttempt {caseId, answers, rubricChecks, selfScore, createdAt}`
- `EssayDraft {essayId, projectFacts, outline, body, updatedAt}`

用户状态与静态题库分离。静态题库升级不得覆盖做题记录。数据库结构需要 schema 版本及升级测试；JSON 备份含 `schemaVersion`、`exportedAt`、用户进度、草稿、尝试记录；恢复前校验，出错给友好提示并不破坏原数据。
