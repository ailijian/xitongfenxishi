## K042 静态/动态测试（A级）

**一句话：**静态测试是不运行程序就检查问题；动态测试是运行程序观察行为。

**为什么要学：**医院新上线的预约系统必须既检查需求和代码的问题，也验证用户真实操作能否成功。

**医院场景：**代码评审发现取消预约接口没鉴权；运行测试发现退款后页面仍显示“待退款”。

### 1. 静态活动
需求评审、设计走查、源代码审查与静态分析，不需要执行被测功能。

### 2. 动态活动
单元、集成、系统、验收或性能测试，通过运行软件比较实际行为与预期。

### 3. 不同阶段协作
代码审查可以提早发现空指针风险；运行负载才能观察真实高并发时延。

### 4. 没有谁能完全替代谁
静态检查可以指出代码可能越权，但实际权限绕过也需动态验证；测试人员还要关注环境。

**示范解题过程**

1. 设计人员审查取消预约流程，发现没有核对操作者身份，属于静态评审。
2. 开发者提交代码，静态扫描指出敏感日志输出。
3. 测试在不同账户下运行API，检查是否能越权取消。
4. 分别记录评审缺陷与动态测试缺陷，修复后做回归。

**易错：** 静态测试不等于“人工检查”，自动静态扫描也属于静态；动态不等于只有UI点击。

**考试提示：** 案例会要求解释为何只做功能测试不足，还需评审与静态扫描。

**记忆口诀：** 不运行叫静态，跑起来叫动态。

**闭卷问答：**

1. 代码走查与接口自动化测试各属哪一类？
2. 高峰P95延迟能仅靠代码审查得出结论吗？

**原创理解题**

**题1：** 团队在不执行预约程序的情况下开展需求评审、代码扫描，属于？
- A. 可用性压测
- B. 动态系统测试
- C. 静态测试
- D. 端到端性能测试
**正确答案：C**
- A解析：更需要实际压测。
- B解析：没有运行被测软件。
- C解析：正确：评审和静态扫描不执行程序。
- D解析：需要运行系统。

**题2：** 要证实高峰期预约接口P95响应不超过2秒，最直接需要？
- A. 统计代码行数
- B. 只看类图
- C. 只审查代码缩进
- D. 执行有明确负载条件的动态性能测试
**正确答案：D**
- A解析：代码长度不决定P95。
- B解析：类图不反映运行性能。
- C解析：缩进格式不能证明响应时间。
- D解析：正确：实际负载与测量才可验收。

## K043 覆盖层级（A级）

**一句话：**测试覆盖率是“跑到了哪些结构”，不是“证明程序没有错”。

**为什么要学：**预约系统分支多，只跑成功预约一条路径会漏掉号源售罄、越权、重复提交等问题。

**医院场景：**函数：如果号源大于0就扣减，否则返回售罄；有两个分支。

### 1. 语句覆盖
让每条可执行语句至少被执行一次，未必触发if的所有真假分支。

### 2. 判定/分支覆盖
每个判定结果至少取到真、假；对于通常控制结构比语句覆盖要求更强。

### 3. 条件覆盖与判定覆盖不同
若if(a && b)，分别让a和b取真/假，不必然覆盖整个判定所有结果；需按题意组合。

### 4. 覆盖高也不能保证无缺陷
业务规则遗漏、错误预期、并发与安全问题都可能出现在100%语句覆盖的程序中。

**示范解题过程**

1. 设函数 if (slot>0) 预约成功 else 售罄。
2. 测试 slot=1 走true分支。
3. 测试 slot=0 走false分支，完成这个单判定的分支覆盖。
4. 再测试 slot=-1 的输入处理，验证边界和业务有效性，而不是只追求覆盖百分比。

**易错：** 条件覆盖和判定覆盖不完全等价；组合条件题先写真值表，不要背“谁一定包含谁”。

**考试提示：** 考选择题易混覆盖类型；案例可用控制流提出测试数据。

**记忆口诀：** 语句看行，判定看真/假，条件看子条件。

**闭卷问答：**

1. if(slot>0)分支覆盖至少需要哪两类测试？
2. 为什么100%语句覆盖仍可能漏掉“未授权用户可预约”？

**原创理解题**

**题1：** 代码 if(slot > 0) success(); else soldOut();，测试仅用slot=5执行了success。可得出什么结论？
- A. 已覆盖两个分支
- B. 测试覆盖率必为100%
- C. 至少成功路径已执行，但不满足该判定的分支覆盖
- D. 已验证所有边界与异常
**正确答案：C**
- A解析：false分支尚未执行。
- B解析：else语句未覆盖，不能断言。
- C解析：正确：未触发0或更小值时的分支。
- D解析：只测一个正数不够。

**题2：** 一个复杂条件判定a&&b，测试使a和b各出现过真、假。能否据此直接断言已完成所有判定组合覆盖？
- A. 不能，仍应检查组合及最终判定结果
- B. 能，只要总语句覆盖100%
- C. 不能，因为覆盖率只能用于性能测试
- D. 能，条件出现真假就保证所有组合
**正确答案：A**
- A解析：正确：条件覆盖、判定覆盖、组合覆盖是不同要求。
- B解析：语句覆盖也不保证所有条件组合。
- C解析：控制流覆盖属于功能逻辑测试。
- D解析：条件取值不代表所有组合都出现过。

## K044 黑盒测试设计（A级）

**一句话：**黑盒测试不看内部代码，而是根据输入、输出与业务规则设计高价值测试。

**为什么要学：**业务人员也能协助验证预约规则；靠随机点按钮不容易覆盖隐藏边界。

**医院场景：**预约系统允许提前1至30天预约，特殊患者在节假日有附加限制。

### 1. 等价类
把规则类似的输入分组，选代表值：1—30天是有效组，0天或31天是无效组。

### 2. 边界值
规则常在临界点出错，重点测0、1、2、29、30、31天。

### 3. 判定表
多个条件组合影响结果，如“有号源/已实名/取消时限内”，列出条件组合与处理结果。

### 4. 状态迁移
订单从待支付到已支付到已取消，各事件是否合法；对非法状态转换也要测试。

**示范解题过程**

1. 从“提前1—30天可预约”划有效与无效等价类。
2. 选择0、1、30、31作为关键边界，必要时补2与29。
3. 写判定表覆盖“实名/号源充足”不同组合。
4. 再补状态规则：已取消订单不能再次取消退款。

**易错：** 等价类是抽样策略，边界值偏临界输入；多个独立条件组合时判定表更直接。

**考试提示：** 案例常要求“设计测试用例并说明方法”，要给实际输入和预期。

**记忆口诀：** 类代表、边界挑临点、组合列判定、状态走迁移。

**闭卷问答：**

1. 1—30天预约的典型边界值有哪些？
2. 实名+有号源+未超限共同决定成功，为什么适合判定表？

**原创理解题**

**题1：** 预约时间允许1~30天，最有代表性的边界数据是哪组？
- A. 只有15
- B. 10、15、20、25
- C. 1、8、16、30
- D. 0、1、30、31
**正确答案：D**
- A解析：一个中间值不足验证边界。
- B解析：都是有效内部点，漏边界。
- C解析：覆盖部分边界但漏无效相邻值。
- D解析：正确：覆盖边界内部值及外侧相邻值。

**题2：** 预约结果受“实名是否通过”“是否有号源”“医保资格”三个布尔条件组合影响。优先用哪种方法描述规则？
- A. 只统计代码行数
- B. 把需求移交运维后忽略
- C. 判定表
- D. 只用一次随机点击
**正确答案：C**
- A解析：代码行数不描述业务规则。
- B解析：运维不替代测试设计。
- C解析：正确：条件组合与不同业务动作适合判定表。
- D解析：随机点击不保证条件组合覆盖。

## K045 测试金字塔（B级）

**一句话：**测试金字塔建议多做快速可靠的基础测试，少用昂贵、脆弱的全链路测试；比例要因项目而异。

**为什么要学：**医院系统每次改预约规则，若只靠完整手机点单测试，运行慢且定位问题困难。

**医院场景：**开发者可以先测“取消时间规则”，再测数据库事务，最后测手机完成预约。

### 1. 单元测试
验证函数或组件的较小逻辑，如24小时取消规则；速度快，失败容易定位。

### 2. 集成测试
检查多个组件/数据库/API协作，例如扣号源事务与持久化。

### 3. 端到端测试
从患者手机到后端再到订单结果，验证关键用户路径，但成本较高。

### 4. 金字塔是经验模型
基础层多、上层少是常见方向；实际要考虑风险、架构、接口数量，不是固定70/20/10。

**示范解题过程**

1. 先写单位测试覆盖取消时限的边界。
2. 做集成测试保证预约记录和号源变更同事务。
3. 选一条手机成功预约及一条号源不足的E2E场景。
4. 持续执行并观察误报、耗时和真实缺陷漏测情况，调整测试组合。

**易错：** 测试层级多不代表每一层必须重复测所有排列组合；应按风险合理分配。

**考试提示：** 选择题考测试层级与测试金字塔，案例考测试策略安排。

**记忆口诀：** 底座快且多，顶层贵且精。

**闭卷问答：**

1. 一个纯计算函数最适合先写哪层测试？
2. 为什么不能全部依赖端到端点击测试？

**原创理解题**

**题1：** 测试“就诊前24小时内不得取消”的纯函数规则，优先选哪类测试？
- A. 生产压测
- B. 人工论文评分
- C. 单元测试
- D. 全院灾备切换演练
**正确答案：C**
- A解析：压测不针对纯逻辑分支。
- B解析：与软件测试无关。
- C解析：正确：局部规则适合快速单元验证。
- D解析：灾备测试系统恢复能力。

**题2：** 团队拥有大量E2E测试，但每次执行需6小时且经常环境不稳定。比较合理的改进是？
- A. 删除所有单元测试
- B. 把稳定规则下沉到单元/集成测试，保留关键用户路径E2E
- C. 只让运维点击全部页面
- D. 每次失败都直接重跑而不分析
**正确答案：B**
- A解析：减少基础测试会更依赖昂贵E2E。
- B解析：正确：分层提高速度、稳定性和定位效率。
- C解析：手工全量点击更慢。
- D解析：反复重跑可能掩盖真实不稳定因素。

## K046 回归测试（A级）

**一句话：**回归测试是“改了一个地方，再确认原来能用的东西没有被破坏”。

**为什么要学：**修复支付回调重复扣款，可能误伤取消预约、退款和通知逻辑。

**医院场景：**研发修复医保支付回调后，患者现金支付的旧流程突然无法完成。

### 1. 何时需要
缺陷修复、需求变更、依赖升级、配置变化都可能引入回归。

### 2. 怎么选回归集
先覆盖高风险核心链路及变更影响面，再加快速单测和典型端到端路径。

### 3. 自动化的价值
将稳定且频繁执行的检查自动化，及时反馈；人工探索仍适合复杂新场景。

### 4. 回归与重测区别
重测确认“这个缺陷修好了”；回归确认“其他相关功能没被弄坏”。

**示范解题过程**

1. 支付回调增加幂等逻辑，先重测同一回调重复发送的场景。
2. 列影响分析：预约成功、退款、支付状态同步、消息通知。
3. 运行对应单元/集成/E2E回归用例并审查日志。
4. 记录失败原因，必要时补到长期回归集。

**易错：** 修复缺陷后的“同一个失败场景通过”叫重测，但不足以证明没有回归。

**考试提示：** 案例答措施时写“变更影响→回归范围→自动化门禁→结果”。

**记忆口诀：** 重测证实修好，回归防止伤旧。

**闭卷问答：**

1. 支付幂等修复后为什么要测正常支付？
2. 回归集如何按风险排序？

**原创理解题**

**题1：** 开发者修复“退款失败”缺陷后先再次执行原失败用例，再测试正常取消预约流程。后一个动作主要是？
- A. 需求访谈
- B. 静态检查
- C. 单纯性能压测
- D. 回归测试
**正确答案：D**
- A解析：不是需求获取。
- B解析：需要执行软件，不是静态。
- C解析：没有负载指标。
- D解析：正确：确认相关旧功能未受修复影响。

**题2：** 回归测试执行时间有限时，最合理的选例原则是？
- A. 按变更影响面与关键业务风险优先排序
- B. 完全随机抽样且不看变更内容
- C. 永远先跑运行最久的用例
- D. 只选最近添加的UI颜色测试
**正确答案：A**
- A解析：正确：风险驱动优先保护关键路径。
- B解析：随机选例可能漏关键场景。
- C解析：耗时长不意味着风险高。
- D解析：不体现核心风险。

## K047 性能指标（A级）

**一句话：**性能指标要同时看速度、吞吐、错误和资源饱和；P95不是平均值。

**为什么要学：**医院平时预约很快，高峰却有少数患者等几十秒；只看平均响应时间会掩盖尾部体验。

**医院场景：**压测1万次请求，其中95%在2秒内，剩余5%在3—20秒。

### 1. 延迟与分位数
P95≈95%样本响应时间不超过的阈值；P99更关注极慢的尾部。

### 2. 吞吐与错误率
吞吐量=单位时间成功处理的请求数；错误率=失败占比，要定义状态码与业务失败口径。

### 3. 资源利用与饱和
CPU、内存、连接池、队列积压等可提示瓶颈，利用率高不一定是根因。

### 4. 先定义负载条件
并发数、请求组成、数据规模、测量窗口不同，性能指标不可直接比较。

**示范解题过程**

1. 生成1万条预约查询响应时间数据并排序。
2. 取第9500条附近的值估计P95（须说明计算口径）。
3. 同时统计失败数、TPS和数据库连接等待。
4. 若P95改善但错误率暴涨，不能宣布优化成功。

**易错：** P95不是平均值，也不表示“最慢5%平均2秒”；吞吐高也可能是大量失败请求。

**考试提示：** 性能案例常问指标选择、瓶颈定位和方案效果。

**记忆口诀：** 延迟看P95，吞吐看TPS，错误与饱和一起查。

**闭卷问答：**

1. P95=2秒代表什么意思？
2. 两轮压测并发负载不一样时，为什么不能直接比较P95？

**原创理解题**

**题1：** 预约查询P95=2秒，最准确的理解是？
- A. 约95%请求响应时间不超过2秒（依统计定义）
- B. 请求的算术平均值等于2秒
- C. 最慢5%请求响应时间都小于2秒
- D. 所有请求都必须恰好2秒
**正确答案：A**
- A解析：正确：分位数描述样本分布位置。
- B解析：平均值与百分位数不同。
- C解析：最慢5%可能明显大于2秒。
- D解析：P95不描述所有请求相等。

**题2：** 压测优化后吞吐提高，但错误率从0.1%升到12%。应该怎么评价？
- A. 吞吐提高即判定成功
- B. 只看CPU利用率即可
- C. 需结合错误率、延迟和成功吞吐一起判断，不可只看吞吐
- D. 关闭错误日志并重新测试
**正确答案：C**
- A解析：大量失败可伪造吞吐提升。
- B解析：CPU不代表成功率。
- C解析：正确：多指标一起验收。
- D解析：隐藏错误妨碍排查。

## K048 SQA/QC（A级）

**一句话：**SQA 更强调通过过程预防质量问题，QC 更强调检查产品是否满足要求；两者要配合。

**为什么要学：**医院系统如果只在上线前找Bug，修复代价高；质量活动应该贯穿需求、设计、开发和发布。

**医院场景：**一组人在制定代码规范、审查流程，另一组人在执行验收测试和核对缺陷。

### 1. SQA质量保证
通过过程、标准、培训、审计、改进等让正确做事的方法可重复。

### 2. QC质量控制
对实际产品或结果实施检查、测试、评审和度量，识别不符合标准的结果。

### 3. 质量活动不止测试
需求评审、追踪、根因分析、缺陷趋势与发布门禁都与质量有关。

### 4. 相互促进
QC发现某类重复问题，SQA可推动改进开发流程和检查表，从源头减少缺陷。

**示范解题过程**

1. 质量负责人发现预约接口反复漏鉴权。
2. QC用接口测试定位具体越权缺陷并记录。
3. SQA组织根因分析，制定权限评审清单和自动门禁。
4. 后续版本抽样确认该类缺陷是否减少，持续优化流程。

**易错：** SQA是偏过程的保证，不等于“保证测试全部通过”；QC也不只等于测试人员。

**考试提示：** 案例常问质量管理机制与持续改进，不能只答“加强测试”。

**记忆口诀：** QA重过程预防，QC查结果缺陷。

**闭卷问答：**

1. 重复出现越权Bug，仅修复当次代码为什么不够？
2. 需求评审是否属于质量活动？为什么？

**原创理解题**

**题1：** 团队发现每个版本都重复出现越权访问缺陷，推动权限评审清单和代码门禁，更偏向什么活动？
- A. 仅对这次缺陷重新点页面
- B. 质量保证SQA的过程预防与改进
- C. 财务净现值分析
- D. 数据备份恢复
**正确答案：B**
- A解析：单次重测不足减少重复根因。
- B解析：正确：建设规范与过程控制防再发生。
- C解析：财务评估不针对该问题。
- D解析：备份并不防止越权。

**题2：** 测试团队运行接口用例，记录实际返回与规格差异，主要体现？
- A. 里程碑成本估算
- B. 业务流程再造
- C. 质量控制QC
- D. 抽象工厂
**正确答案：C**
- A解析：成本估算不是测试。
- B解析：流程再造不是这里的直接活动。
- C解析：正确：检验实际产品是否符合要求。
- D解析：设计模式不属于质量活动分类。

## K049 LLM辅助测试（A级）

**一句话：**大模型能帮测试人员“想测试点、写草稿”，但不能把生成的断言不加核对就当事实。

**为什么要学：**AI能加快医院系统回归用例构建，但模型可能编造规则、忽略隐私或输出无法运行的脚本。

**医院场景：**把“预约提前1—30天”需求给LLM，让它提出有效、无效与边界测试。

### 1. 适合的辅助工作
从需求草拟等价类、边界值、判定表、自动化脚本骨架与合成数据。

### 2. 人工审核规则
每条预期行为都要对照真实需求与业务方确认，不能把模型编造的“取消后全额退款”当规则。

### 3. 执行与证据
生成的测试代码需真正执行，记录输入、环境、输出与断言结果，能重复跑才有价值。

### 4. 数据安全与可复现
不要上传真实病历、手机号等敏感信息；控制提示版本、模型版本、测试数据和输出审查。

**示范解题过程**

1. 输入已审定的“提前1—30天”预约需求，不上传真实患者资料。
2. 让模型给出0、1、30、31天测试场景并说明预期。
3. 人工核对是否漏掉跨时区、节假日或业务例外。
4. 将审核后的脚本在测试环境执行，失败时追溯需求与实际响应。

**易错：** 生成了20条测试脚本不等于执行通过20条；LLM结论不是官方需求或验收标准。

**考试提示：** 2026相关案例可能考AI辅助测试治理：审核、可追溯、隐私与复现。

**记忆口诀：** AI给草稿，人审规则，机器执行，证据留存。

**闭卷问答：**

1. LLM声称“退号全额退款”，但正式需求无此规则，怎么处理？
2. 使用AI生成测试脚本时为什么要保存环境和断言结果？

**原创理解题**

**题1：** LLM依据需求说明生成了50条接口用例。团队下一步应优先做什么？
- A. 人工审核与需求追踪，再实际执行和记录证据
- B. 允许模型上传真实患者完整资料增强准确性
- C. 直接将模型输出作为正式验收结论
- D. 删除需求文档，以生成内容为准
**正确答案：A**
- A解析：正确：审核预期并执行才能获得测试证据。
- B解析：敏感数据上传有隐私风险。
- C解析：未审核未执行不能宣布通过。
- D解析：源需求仍是权威依据。

**题2：** 为了提高生成测试的可复现性，哪项做法最好？
- A. 记录提示、需求版本、测试数据和执行环境，并人工核对断言
- B. 每次只要求模型“再试一次”，不留历史
- C. 不审查生成SQL直接运行生产数据库
- D. 测试失败时删除失败用例
**正确答案：A**
- A解析：正确：版本、数据、环境和断言能追踪和复现。
- B解析：输出随机性可能导致复现困难。
- C解析：生产执行未审SQL风险高。
- D解析：删除失败证据不利改进。

## K050 数据安全（A级）

**一句话：**数据安全是一整条链：弄清什么数据敏感、谁能看、怎么存传、留多久、如何审计删除。

**为什么要学：**预约系统处理手机号、身份信息和病历，单靠HTTPS不能解决员工越权、数据库泄露或过度留存。

**医院场景：**患者希望护士能查看当班预约名单，却不能随意读取所有患者的病历。

### 1. 分类分级与最小必要
区分公开排班、手机号、健康记录等不同敏感程度，按业务必要性决定收集范围。

### 2. 授权与最小权限
按岗位、就诊关系和使用目的授予操作权限，不能所有医护共享管理员账号。

### 3. 技术保护
传输加密、存储加密/密钥管理、脱敏展示、日志审计、访问告警。

### 4. 生命周期治理
制定访问复核、保留期限、备份删除、数据导出与应急处置，形成可操作制度。

**示范解题过程**

1. 列数据目录：排班公开、预约联系人敏感、病历高度敏感。
2. 根据医生、护士、收费岗位确定最小读写范围。
3. 对手机号做部分掩码显示，必要字段存储加密并控制密钥。
4. 记录访问审计并定期检查越权和到期数据清理。

**易错：** “用了HTTPS所以数据安全”是典型错误：HTTPS只保护传输路径的特定风险。

**考试提示：** 案例要写分类分级、授权、加密、脱敏、审计、留存全链路。

**记忆口诀：** 分类、授权、保护、审计、清理。

**闭卷问答：**

1. 护士有查看预约记录权限，是否自动有权查看全部病历？
2. 为何传输加密后数据库仍可能需要加密或访问控制？

**原创理解题**

**题1：** 系统启用HTTPS后，数据库管理员仍能直接读取所有患者明文资料。最需要补强什么？
- A. 只增加服务器带宽
- B. 存储端访问控制、数据加密及审计
- C. 把TLS证书有效期缩短到一小时
- D. 把页面主题改深色
**正确答案：B**
- A解析：带宽不能限制内部访问。
- B解析：正确：HTTPS不能代替静态存储与内部权限管理。
- C解析：证书轮换不能解决数据库过度授权。
- D解析：外观与数据泄露无关。

**题2：** 医生为完成复诊工作仅需访问自己接诊患者的必要记录。授权最符合什么原则？
- A. 按最小必要和业务关联授予数据访问
- B. 任何登录者都能下载全院病历
- C. 先开放所有字段，出事故再限制
- D. 所有医生共享超级管理员账号
**正确答案：A**
- A解析：正确：数据与岗位、关系、目的匹配。
- B解析：构成明显越权。
- C解析：事后补救不替代预防。
- D解析：共享高权账号无法追责。

## K051 AES/RSA/哈希（A级）

**一句话：**AES 用同一把密钥加解密；RSA/ECC 等公钥密码让公钥与私钥承担不同角色；哈希生成摘要不是加密。

**为什么要学：**安全题常把Base64、哈希、对称加密、非对称密钥混在一起，理解用途才能不丢基础分。

**医院场景：**医院需要保护数据库中的联系方式，并确认下载的安装包未被篡改。

### 1. 对称加密 AES
加解密用共享秘密密钥，适合大批量数据；要妥善管理密钥、模式和随机数。

### 2. 非对称密码 RSA/ECC
公钥与私钥配对，常用于密钥交换、数字签名或公钥加密方案，具体依算法/协议而定。

### 3. 哈希 SHA-256
把输入映射为固定长度摘要，设计目标是难以逆向且抗碰撞；可用于完整性校验，不能从摘要恢复原文。

### 4. 编码不是加密
Base64能被任何人解码；密码存储通常应使用专门的带盐慢哈希/KDF而非普通SHA-256直接算一次。

**示范解题过程**

1. 患者联系方式需要保密存储，选择合适模式的AES并管控密钥。
2. 传输访问用TLS，证书及公钥机制协助建立受认证的安全信道。
3. 下载软件时比较可信渠道发布的SHA-256摘要可辅助完整性检查，但防篡改还需可信发布来源/签名。
4. 密码不要可逆存储，使用适当的密码哈希方案和盐。

**易错：** 哈希不是加密；RSA/ECC并不意味着拿公钥“加密所有大文件”；Base64完全不保密。

**考试提示：** 重点区分机密性、完整性、认证及数字签名的使用目标。

**记忆口诀：** AES对称护数据，公私钥做认证/交换，哈希看摘要。

**闭卷问答：**

1. 为何Base64编码后的手机号仍属于明文泄露风险？
2. 哈希校验和数字签名在可信来源方面有什么区别？

**原创理解题**

**题1：** 医院需要保护数据库中大量患者联系方式的机密性，通常优先选用？
- A. Base64编码
- B. AES对称加密并安全管控密钥
- C. SHA-256摘要替代可恢复联系方式
- D. 仅使用CRC校验
**正确答案：B**
- A解析：编码能直接解码，不提供保密性。
- B解析：正确：对称加密适合保护大量需恢复的业务数据。
- C解析：哈希不能恢复手机号供合法业务使用。
- D解析：CRC偏差错检测，不提供机密性。

**题2：** 若用户密码只进行一次普通SHA-256后存库，最佳改进是？
- A. 把散列值再Base64两遍
- B. 使用带随机盐的专用密码哈希/KDF并配置合理成本
- C. 把密码直接写在日志以便找回
- D. 删除盐并保持固定散列结果
**正确答案：B**
- A解析：Base64不提升密码存储抗暴力猜测。
- B解析：正确：专用密码哈希方案增加攻击成本。
- C解析：明文日志是严重隐私与安全风险。
- D解析：无盐容易暴露同密码和遭预计算攻击。

## K052 授权RBAC/ABAC（A级）

**一句话：**RBAC 看“你是什么角色”；ABAC 还看“谁、访问什么、现在什么环境”。

**为什么要学：**医院护士角色可以查预约，但只有当班且负责的病区才能看某些敏感数据。

**医院场景：**患者A只能看自己的记录，护士可以看当班患者，医生需有接诊关系。

### 1. RBAC 基于角色
权限授予角色，再把用户分配到角色，例如“预约客服能取消未支付订单”。

### 2. ABAC 基于属性
按主体、资源、动作、环境属性决定，例如医生所属科室、患者就诊关系、时间。

### 3. 两者可以结合
RBAC控制基础功能范围，ABAC细化行级/场景访问；管理员不等于对所有病历永远可见。

### 4. OAuth2是什么
OAuth2是授权框架，用于委托访问令牌，不是RBAC/ABAC的同义词，也不代替应用业务鉴权。

**示范解题过程**

1. 先列角色：患者、医生、护士、预约客服。
2. 给角色分配预约查看、修改、取消等功能操作权限。
3. 对“看病历”再校验患者关系、医生所在科室和时间等属性。
4. 对拒绝访问输出可追溯审计，定期复查角色与属性策略。

**易错：** 登录成功仅证明某身份经过认证，不自动表示有任何病历访问权限。

**考试提示：** 案例常问多角色和细粒度权限设计；要区分认证与授权。

**记忆口诀：** RBAC看角色，ABAC看条件。

**闭卷问答：**

1. 护士角色拥有读取权限，为什么还需要患者或病区属性？
2. OAuth2令牌有效是否就能访问所有API？

**原创理解题**

**题1：** 只有“当前负责该患者且在值班时间的医生”能访问某份病历，使用哪种授权方式更直接？
- A. 把权限写进前端按钮CSS
- B. 仅按医生角色的RBAC，不做任何条件判断
- C. ABAC结合主体、资源及环境属性
- D. Base64对令牌编码
**正确答案：C**
- A解析：前端隐藏不能保护后端接口。
- B解析：角色不能单独表达当前接诊关系与时间。
- C解析：正确：动态属性条件正是ABAC擅长的。
- D解析：编码与授权逻辑无关。

**题2：** 用户带有效OAuth2访问令牌调用“查看病历”API，系统仍应做什么？
- A. 核验该令牌对本资源/操作有授权，并应用业务权限约束
- B. 只要令牌格式正确就允许访问所有病历
- C. 把令牌复制到公开审计页面
- D. 关闭所有访问日志
**正确答案：A**
- A解析：正确：令牌不自动覆盖资源级业务权限。
- B解析：造成越权访问。
- C解析：泄露凭证风险。
- D解析：审计有助追踪敏感访问。

## K053 最小权限（A级）

**一句话：**最小权限就是只给完成当前任务真正需要的能力，并限制范围、时长和次数。

**为什么要学：**医院的AI客服能查询预约，不能因为“要帮用户”就拥有直接删除病历或批量转账的权限。

**医院场景：**AI Agent 被授权查询自己的预约单，随后遇到用户要求“帮我删掉其他人的预约”。

### 1. 谁需要什么
按角色/服务账号授予最小操作集合，读与写、查看与删除分开。

### 2. 作用域和时间
令牌范围限定患者、院区或项目；短期任务可采用到期授权和权限提升审批。

### 3. 高风险操作
退款、病历导出、批量取消等应要求显式确认、授权验证和审计。

### 4. 代理同样受约束
LLM代理调用工具也必须走后端权限校验，不能信任提示词、模型自称的身份或外部网页指令。

**示范解题过程**

1. 列出客服代理允许的工具：queryOwnBooking、cancelOwnBooking（需确认）。
2. 对工具调用携带不可伪造的用户身份，并在服务端校验订单归属。
3. 批量取消或退款转人工确认/双重审批。
4. 记录调用链、结果与失败原因，定期回收多余权限。

**易错：** 最小权限不只是“用户角色低”，还包括工具、资源范围、时效和目的；前端限制不是安全边界。

**考试提示：** AI案例问工具安全时写“白名单、服务端鉴权、敏感操作确认、审计”。

**记忆口诀：** 只给所需、限定范围、到期回收。

**闭卷问答：**

1. Agent“自己判断用户已授权”是否足够？
2. 哪些操作适合额外人工确认？举两个例子。

**原创理解题**

**题1：** 预约AI助手只需查看当前用户的预约。以下权限配置最符合最小权限？
- A. 拥有全院数据库管理员权限
- B. 可查询任何患者病历，以备不时之需
- C. 仅授予查询本人预约的受控接口与短期令牌
- D. 允许执行任意由模型生成的SQL
**正确答案：C**
- A解析：明显超出业务需要。
- B解析：“以备不时之需”不是合法最小需求。
- C解析：正确：工具与资源范围被精确限制。
- D解析：任意SQL会放大权限与注入风险。

**题2：** 医院决定让AI助手执行高额退款，哪项控制最关键？
- A. 模型输出流畅即可自动转账
- B. 增加服务端授权和人工确认、额度校验、审计记录
- C. 把付款密钥写入提示词方便调用
- D. 只在页面上隐藏“退款”字样
**正确答案：B**
- A解析：自然语言质量不代表授权。
- B解析：正确：敏感资金操作必须有独立业务控制。
- C解析：密钥写进提示词易泄露。
- D解析：页面文字不限制后台API。

## K054 RPO/RTO（A级）

**一句话：**RPO 问“最多能丢多久的数据”，RTO 问“最多能停多久的服务”。

**为什么要学：**医院系统崩溃时，业务最关心“能恢复到什么时间点”和“什么时候可以重新挂号”。

**医院场景：**医院要求最多丢失15分钟的预约记录，预约功能中断不超过2小时。

### 1. RPO恢复点目标
最大可接受数据损失时间窗口：若故障在12:00，RPO=15分钟意味着恢复点应尽量不早于11:45。

### 2. RTO恢复时间目标
故障发生到关键服务恢复的最大可接受用时，此例不超过2小时。

### 3. 目标由业务决定
对挂号、支付、日志分析可设不同目标，并据此决定复制和备份策略。

### 4. 要靠演练证明
备份频次满足RPO还不等于恢复速度满足RTO，需要做切换和恢复测试。

**示范解题过程**

1. 业务给出RPO=15分钟、RTO=2小时。
2. 推算12:00故障时可接受的最早恢复数据时间点为11:45。
3. 选择备份/复制方式，考虑故障场景与复制延迟。
4. 安排真实恢复演练，记录丢失范围和服务中断用时是否达标。

**易错：** “15分钟能恢复服务”是RTO不是RPO；“最多丢15分钟数据”才是RPO。

**考试提示：** 该考点适合直接出案例与计算题，须结合故障时间线说明。

**记忆口诀：** PO记数据时间点，TO记恢复耗时。

**闭卷问答：**

1. 12:00故障，RPO=15分钟，最早可接受恢复点是什么时候？
2. 备份每5分钟一次是否能保证RTO=2小时？

**原创理解题**

**题1：** 医院要求“故障时最多丢失15分钟预约数据”，定义的是？
- A. SLA=15分钟
- B. RTO=15分钟
- C. RPO=15分钟
- D. MTTR=15分钟
**正确答案：C**
- A解析：SLA是服务等级约定。
- B解析：RTO是可接受中断时长。
- C解析：正确：RPO约束可接受数据丢失时间窗口。
- D解析：MTTR是平均修复/恢复指标。

**题2：** 医院RPO=10分钟，RTO=1小时。12:00出现故障，以下哪个目标描述正确？
- A. 必须在12:10恢复服务，不能丢任何数据
- B. 应在13:00前恢复关键服务，并争取数据点不早于11:50
- C. 只要每小时备份一次就必然满足两个目标
- D. 数据必须恢复到13:00之后
**正确答案：B**
- A解析：混淆RPO与RTO，且把允许损失说成零。
- B解析：正确：中断不超过1小时，恢复点最多落后10分钟。
- C解析：备份间隔1小时可能不满足RPO，也不保证恢复速度。
- D解析：13:00在故障后，不能凭空恢复不存在的记录。

## K055 备份演练（A级）

**一句话：**备份成功不等于能恢复；真正可靠的容灾需要隔离备份、验证恢复、切换和回切演练。

**为什么要学：**医院如果遇到勒索软件或误删数据库，仅显示“备份任务完成”无法保证重要病历还能用。

**医院场景：**运维每天备份预约数据库，但从未试过从备份恢复；某天数据库损坏才发现备份文件不可读。

### 1. 备份策略
区分全量/增量/日志等方式；按数据重要性与RPO选择频率。

### 2. 隔离与不可变
将关键副本隔离在不同权限或位置；不可变副本可降低勒索软件连备份一起改坏的风险。

### 3. 恢复演练
在隔离环境按步骤恢复库、验证完整性及关键业务一致性，记录耗时和恢复点。

### 4. 切换与回切
不仅要知道主系统坏了怎么切到备系统，还要知道主系统修复后怎么避免数据分叉地切回来。

**示范解题过程**

1. 检查医院现有备份：每日完整、每15分钟日志、异地不可变副本（示例）。
2. 每季度在隔离环境按恢复手册还原数据库。
3. 运行预约、取消与库存一致性测试，记录RPO/RTO是否达标。
4. 模拟故障切换后再演练回切，核查是否发生双写或丢单。

**易错：** 备份频率是实现RPO的一个因素，恢复演练才验证RTO与备份可用性。

**考试提示：** 案例答题要有“备份、验证、切换、回切、审计”闭环。

**记忆口诀：** 有备份不算数，恢复成功才算数。

**闭卷问答：**

1. 为什么备份任务显示绿色仍可能发生不可恢复事故？
2. 切回主数据中心前应核对什么？

**原创理解题**

**题1：** 运维每天确认备份任务成功，但从未尝试恢复。最严重的管理缺口是？
- A. 没有验证备份可恢复性和业务一致性
- B. 没有使用更多监控界面颜色
- C. 没有把备份文件改名
- D. 没有把数据库和缓存放在同台服务器
**正确答案：A**
- A解析：正确：未演练无法证明恢复数据和耗时满足目标。
- B解析：UI外观与可恢复性无关。
- C解析：文件名不能代表备份正确。
- D解析：同机部署还可能增加单点风险。

**题2：** 勒索软件能拿到生产管理员权限时，哪项措施最能提高关键备份存活概率？
- A. 把备份存到与生产同权限同目录
- B. 将备份隔离并使用不可变存储及独立权限
- C. 停用所有备份以减少攻击面
- D. 只把文件扩展名改成.bak
**正确答案：B**
- A解析：攻击者可一并删除或加密。
- B解析：正确：隔离权限与不可变性增强抗破坏能力。
- C解析：无备份风险更大。
- D解析：扩展名不提供隔离保护。

## K074 SLA/MTTR（B级）

**一句话：**SLA 是服务双方约定的“服务质量合同”；MTTR 是发生故障后平均要多久恢复。

**为什么要学：**医院采购云系统时，不能只听厂商说“很稳定”，应有明确可用性、响应、故障处理和补偿约定。

**医院场景：**服务合同规定月可用性99.9%、一级故障2小时内恢复，运维记录多次故障实际修复耗时。

### 1. SLA服务等级协议
约定服务范围、指标口径、统计期、责任边界、排除条件与违约处理。

### 2. 可用性计算需定义
按哪个月、哪些接口、计划维护是否计入，都要写清，不能只写“99.9%”。

### 3. MTTR平均修复/恢复时间
用多次故障的恢复耗时合计除以故障次数；要在项目内统一“修复”还是“恢复”的口径。

### 4. 指标要闭环
监测、告警、升级、故障记录与复盘共同支持SLA，不是一份无人测量的合同。

**示范解题过程**

1. 假设三次故障分别恢复用时20、40、60分钟。
2. MTTR=(20+40+60)/3=40分钟。
3. 核对SLA是否按月统计可用时间、是否排除计划维护。
4. 若违反SLA，按合同进行升级、责任核实和服务改进。

**易错：** MTTR是平均值，不是每次故障最长时长；SLA目标与实际运行指标需明确区分。

**考试提示：** 综合知识常考SLA、MTTR定义和可用性计算；案例考服务监控。

**记忆口诀：** SLA定约定，MTTR算平均修复。

**闭卷问答：**

1. 三次恢复耗时分别10、20、60分钟，MTTR是多少？
2. 为什么SLA应写明统计口径和责任边界？

**原创理解题**

**题1：** 三次故障恢复耗时为20、40、60分钟，按算术平均定义的MTTR是？
- A. 120分钟
- B. 30分钟
- C. 40分钟
- D. 60分钟
**正确答案：C**
- A解析：120是总和。
- B解析：总时长120，除以3才是平均。
- C解析：正确：120/3=40分钟。
- D解析：60是最大单次时长。

**题2：** 一份SLA只写“系统保证高可用”，但未定义统计期和测量对象。最直接问题是？
- A. 开发语言自动限定为Java
- B. 不方便客观验收、统计和追责
- C. 服务必然不能部署多机
- D. 系统无法使用HTTPS
**正确答案：B**
- A解析：编程语言与SLA无关。
- B解析：正确：缺少可测指标与责任口径。
- C解析：协议文本不直接决定部署方式。
- D解析：TLS无关。
