# Codex 接入指令：第一天零基础课程内容包

## 背景与目标

用户完全没有系统分析师基础。当前 `/knowledge/K001` 直接显示原卡中的抽象术语，导致读不懂。现提供一套 **实际写完的 15 张知识卡入门课程**，不要再只给出设计方案。目标是让初次接触术语的人，通过医院预约业务故事完成理解、演示、原创练习、闭卷自述。**本次只升级教学展示层，保留现有验证与存储规则。**

## 交付文件

- `day1_beginner_lessons.json`：可机器读取的 15 课结构化内容，含每课 2 道原创练习及逐项解析。
- `day1_beginner_guide.md`：完整学生讲义，供内容核对和无网站情况下学习。
- `CONTENT_CHECKLIST.md`：关键一致性和安全规则。

课程对应原卡 ID：`K001`—`K014`、`K075`；**不是 K015**，不得改变原 D1 分配。源代码 `src/data/knowledge.json` 里的 `essentials`、`pitfalls`、`priority`、`relatedQuestionIds`、`sourceRef` 均保持原样。`docs/learning-content-gap.json` 的 261 个待审 CP 不得被本包自动设置为 approved。

## 必须实现

1. 将本包放在 `src/data/lessons/day1_beginner_lessons.json`（或等价路径），写严格类型定义和静态数据验证器。检查15个原卡ID存在、唯一；30道练习题ID唯一；答案必须是A-D之一；内容文本完整、无HTML脚本执行。
2. 知识详情默认首先显示“这一课要解决什么→生活化业务场景→循序讲解→一步步做示例→容易混淆→原创课后理解练习→闭卷自述”，原 `essentials`/`pitfalls` 折叠放在“考前速记”；避免一进页直接展示抽象速记内容。
3. 每课最多先显示一个解释步骤，允许“懂了，下一步”依序展开，也有“看全部”；读过不自动标记为首轮通过。
4. 两道原创练习使用与正式 RK 题库完全分离的组件与ID；**作答提交前隐藏答案及所有逐项解析**。提交后明确解释 A/B/C/D 对错原因，允许重做并显示原因。不得把本包原创练习偷偷标记成官方真题。
5. 原有的“闭卷自测”入口始终可用；课后要求用户不看资料自己复述。不要用本包练习的完成数自动篡改 `CardAttempt`、客观验证、巩固通过或原本带24小时门槛的逻辑。本包 practice-only，后续要计入客观验证需单独内容审核和题卡关联复核。
6. 知识点 K004、K005、K010、K011 在原题库缺少可信日常章节题，依然按原 `self-check-only` 标示，不得因本包提供原创练习就自动变成 verified。
7. 对其他 61 张卡保留原布局（可出现“当前为考前速记版”的诚实提示），不要把课程文案复制粘贴到不相关章节，也不要生成空白假课程。
8. 保留所有既有内容与用户记录 ID。除非明确必要，**本轮不做 v3 数据迁移**；本包是纯静态 UI 附加内容，避免触碰数据库、备份版本及历史记录。
9. 手机优先：375/390宽度、长文字换行、讲解步骤切换、按钮聚焦与可访问性、底部导航不遮挡；折叠“考前速记”和“解析”。支持离线 Service Worker 新包缓存。
10. `conceptVisual` 可选，内含 8 个便于零基础理解的图示说明。渲染器优先使用现有轻量、可离线的 SVG/流程渲染方案；若选 Mermaid，必须限制输入为构建时静态受审内容，禁止执行任意 HTML 或脚本，测试所有图语法，手机宽度超出时可滚动/缩放并保留可阅读的文本替代。用例/DFD等示意图已经声明非正式 UML/DFD 符号，不得把简化示意误标为规范图。
11. 发布前完成构建、测试、实际课程逐张抽查、对原75+75题答案门禁回归，确保离线和进度持久化没有回归。

## 验收场景（不可以只交截图）

- 新用户访问 K001：首先看到“一句话 + 医院预约情境”，不用提前懂 NFR/UML；完成解释后才碰到原“必会概念”。
- K001 原创练习答错后能看到为什么错；返回再选答案，未提交前不能露出答案。
- K006 能区分 include 和 extend；K007 能区分 alt/opt/loop；K008 能区分分支与并行；K010 能理解组合的生命周期约束；K011 能找到不合法 DFD 直连。
- D1 15课都能显示：每课至少4个讲解步骤、4步带做示例、2道原创题及逐项解析、2个闭卷问题。
- 刷新、换页面、后台回来、断网重开：原先学习数据完全保留；关闭课程说明不会被算作通过。
- K004/K005/K010/K011 的旧验证方式保持不变；已有未提交模考答案不会从本课程页泄露。

## 交付顺序

1. 先本地接入 15 课并展示 K001 与 K010 的手机截图。
2. 跑现有测试和新增课程专项测试，输出 `docs/beginner-course-integration-report.md`。
3. 所有自动化测试和源码审核通过后才部署 staging。保留以前备份与用户记录。
4. 本阶段完成后，按同一教学质量和统一业务故事逐批开发 D2—D5 的剩余61课；不得先用批量空模板糊弄覆盖率。

不要通过把讲解藏进一个随意不完整的弹窗来交付。核心是让无基础用户真正理解并解决问题。
